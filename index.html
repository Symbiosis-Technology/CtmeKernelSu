同一个应用，两条执行通道

能不能装模块、能不能改系统，取决于你手里这台机器走的是哪条路，而不是应用本身。

root 通道

KernelSU 内核 + 管理器签名
  • 01内核侧 su，uid 0 真实生效
  • 02模块可覆盖挂载，重启后依然在
  • 03超级用户可给其它应用授 root
  • 04文件管理可直读 /data 与 /data/adb

前提：内核已集成 KernelSU，且管理器签名被编进内核白名单。没有这一步，root 相关项全部为假。

shell 通道

Shizuku 授权 · uid 2000
  • 01执行命令、读写 /sdcard 与 /data/local/tmp
  • 02pm grant / appops 这类 shell 级权限可调
  • 03插件 action.sh 脚本可以跑
  • 04模块可安装、可管理，但不能内核级挂载

前提：设备上装有 Shizuku 并在弹窗里对本应用选「始终允许」。授权掉了，命令会直接返回 Permission Denial。

插件目录长什么样

对齐 AxManager 的 module.prop 规范：一个插件一个目录，id 必须字母开头。应用私有目录，不需要授权也能装、能开关。

plugins/ └─ bt_sound_booster/ ├─ module.prop # 必填 ├─ action.sh # 可选，点「运行」触发 ├─ service.sh # 可选，常驻脚本 ├─ disable # 空文件 = 已禁用 └─ webroot/ └─ index.html # 可选，WebUI 入口
module.prop
id=bt_sound_booster
name=BT Sound Booster
version=v1.2.0
versionCode=3
author=共生科技
description=蓝牙连接后把媒体音量拉满
axeronPlugin=30000

页面里的 WebUI 用 ksu.exec("id") 就能拿到输出， 同时兼容 Axeron 与 CtmeBridge 三个名字，写法不同也能跑。

做不到的事，写在明面上

这些不是 bug，是 Android 的权限模型决定的。省得你装完期待落空。

内核级模块挂载

没有 KernelSU 内核时，模块只能装、能跑脚本、能开 WebUI，但不能覆盖挂载到系统分区。shell 的 uid 2000 写不了 /data/adb。

给别的应用授 root

让其它进程看到 uid 0，需要内核侧能力。本应用能做的是 shell 级授权（pm grant / appops），不是 root。

替 Shizuku 授权

若系统把 Shizuku 权限定为 signature 级，只有 Shizuku 本体能写它的授权名单，第三方 pm grant 会被拒绝并原样回显错误。

常见问题

这和官方 KernelSU 是什么关系？

没有官方关系。它复用 KernelSU 官方管理器的源代码与包结构，改了 applicationId 与名称，属于个人第三方构建，不是 KernelSU 团队发布的版本。

没有 root，为什么模块页还能装模块？

因为插件装在自己的应用私有目录里，安装、列目录、启用/禁用都走应用自身文件权限，不需要 shell。真正让模块影响系统，仍然要有内核。

终端里命令一直不出结果怎么办？

2.7.0 修了两个会假死的问题：stdout/stderr 串行读取导致的互锁，以及 waitForTimeout 单位名传错被误判成超时。现在改成双流并发读 + 轮询 alive()，15 秒没返回会明确报超时。

「Shizuku 授权」开关点了，对方应用还是说没授权？

把开关弹出的 toast 原文看一遍。若是 not a changeable permission type，说明该权限是 signature 级，pm grant 无法生效，只能由 Shizuku 本体去授。

AI 助手会把我的命令发到哪里？

对话内容发往智谱开放平台的 chat/completions 接口（glm-4-flash）。命令默认不会执行，必须你在弹窗里点「执行」才会跑，且只以当前 root / shell 身份执行。
